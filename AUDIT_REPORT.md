# Thesis repository audit — 28 October 2026

Scope: local code, recorded prompts and model metadata, run artifacts, analysis scripts, statistical plan, headline claims, and the closest cited prior work. This is an evidence audit, not a rerun of GPU training. Isaac Gym and the remote LLM endpoints are unavailable locally. No claim of complete scientific validation follows from static checks.

## Findings to resolve before the write-up

1. **H2 significance is unsupported (high).** `final_analysis.py` lines 139–175 shuffles the `indep`/`batch4` labels across calls while keeping each call's token count and number of valid rewards attached. A batch call can produce four rewards; an independent call can produce one. These calls are not exchangeable under that permutation. The printed `p = 0.0` is a Monte Carlo count, not an exact zero, and its null distribution is invalid. The four observed task ratios (2.68, 3.75, 2.58, 5.49) are real descriptive savings. The task-level one-sided sign test already stored in `results/final/h2.json` is 0.0625. The test uses 48 calls, not the 70 stated in the former summary table. Do not claim a corrected significant H2 result until a defensible test is specified and run. The primary-hypotheses JSON and older prose retain the original invalid p-value as historical output.

2. **H1 inference is too narrow for a general claim (high).** The 175 four-reward subsets reuse seven rewards on five seeds. `final_analysis.py` lines 78–88 resamples subsets inside each seed, giving an optimistic `p = 0.0019` and Holm `0.0076`. The existing conservative analysis treats each seed as one observation: `p = 0.041` one-sided, Holm `0.21`. Moreover, the rule was selected after seeing seeds 4–5, then tested on all five seeds. Seeds 7–9 are the cleaner untouched test, but only three seeds. Report the observed 0.997 versus 0.972 retained fraction as a result for this reward pool, with uncertainty and the selection history. A new-reward evaluation is needed for transfer claims.

3. **Held-out library includes held-out human curves (medium).** `pruning/heldout.py` lines 76–90 adds every human curve to each world library, including the test seed. Replaying the 175 worlds with only training-seed human curves changed VoI retention from 0.996616 to 0.996074 and cost from 0.424595 to 0.427548; fixed@500 remained at 0.971601 retention and 0.375 cost. This does not reverse the comparison, but the reported score is not a strictly prospective library evaluation. Freeze the library inputs per split and regenerate the H1 table before finalizing it.

4. **H3 uncertainty is understated or at least unverified (medium).** `final_analysis.py` lines 178–233 bootstraps individual candidate run scores. Four candidates from one batch call share a generation event, and the same candidate is trained on multiple seeds. The registered plan calls for task/seed clusters and candidate resampling within clusters. Two Humanoid runtime failures are omitted because they have no curve, even though they are failed generated rewards. H3 is already inconclusive; retain that conclusion and avoid using its CI or `p = 0.064` as definitive until cluster and failure sensitivity analyses are done.

5. **Model provenance field is wrong in the Gemini/Qwen derived records (medium).** `gen_task.py` used the imported MiniMax default for `model_requested` during the robustness build. In 55 `generation.json` files, `model_requested` differs from `model_used`; the associated `reply*.json` request and response both show the intended Gemini or Qwen model. The generation behavior appears correct; the derived metadata is wrong. The builder now copies the request model. Preserve historical raw reply files and correct or annotate the affected derived metadata before packaging a replication archive.

6. **Ledger and manifest had stale/inaccurate totals (low).** The ledger previously assumed 4,096 environments and horizon 16 for every task. Cartpole has 512 environments, and Humanoid has horizon 32. The corrected 451,000 PPO iterations represent 30,236,672,000 environment steps. The manifest's 376 phases and 431,000 iterations were stale; the actual ledger has 384 phases (280 initial, 104 resumed). The separate live-pruning run has no `result.json` and is outside that ledger. The bookkeeping code, ledger output, and manifest totals are corrected.

## Write-up status

The code and artifacts support a descriptive thesis about compute savings and the limits of early screening. They do **not** yet support the current primary-test significance claim for H2, and H1 significance depends on a test that understates dependence and a partially selected test set. Keep the conservative H1 wording, present H2 ratios as descriptive, and rerun a clean analysis of H1/H2/H3 before freezing thesis tables.
